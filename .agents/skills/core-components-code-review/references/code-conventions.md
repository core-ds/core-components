# Соглашения кода, CSS и токены

Чек-лист собран из повторяющихся замечаний мейнтейнеров в ревью PR этого репозитория (2022–2026) и из `docs/development-faq.stories.mdx`. Текст в кавычках-«ёлочках» — формулировки из этих замечаний. Каждое правило встречалось в ревью многократно и у разных ревьюеров, то есть это практика команды, а не вкус одного человека.

**Все правила ниже — про новый и изменённый код.** В репозитории много старого кода, который им не соответствует: `type` вместо `interface`, буквенные размеры, файлы в camelCase, узлы без `dataTestId`. Несоответствие в строках, которые PR не трогает, — не finding (см. «False positives» в `SKILL.md`).

## Типы и именование

- **Новые типы props — `interface`, не `type`.** Просьба «мб сразу в interface?» повторяется у нескольких ревьюеров.
- **Венгерская нотация не используется:** никаких `IProps`, `TProps`, `sBackground` — «мы не используем венгерскую нотацию».
- **Обработчики событий внутри компонента — `handleSomethingClick`**, не `onSomethingClick` (`docs/development-faq.stories.mdx`). Callback'и наружу — сигнатура `(event, payload) => void` (там же).
- **Размеры — числовые** (`size?: 32 | 40 | 48 | 56`, как в `packages/button/src/typings.ts`). Буквенные `s/m/l` — deprecated: «ставь по возможности числовые размеры, буквенные уже deprecated». Примеры с буквенными размерами в `docs/development-faq.stories.mdx` устарели — не ссылайся на них как на образец.
- **Файлы — kebab-case** (`human-file-size.ts`, не `humanFileSize.ts`).

## Структура компонента

- **`dataTestId`** прокидывается в `data-test-id` корневого элемента; для вложенных элементов — `getDataTestId` из `@alfalab/core-components-shared`. Новый компонент или новый **смысловой** вложенный узел без этого — finding. Смысловой — тот, который потребитель ищет в тестах (шапка, контент, футер, кнопка). Служебные узлы — невидимые измерительные `div`, обёртки, маркеры — идентификатора не требуют: у самих компонентов библиотеки их тоже нет.
- **`displayName`** обязателен, включая обёртки (`forwardRef`, HOC): «добавь везде где обернул displayName».
- **Хуки — только на верхнем уровне компонента**, не в условиях. `Component.responsive.tsx` рендерит напрямую `*Desktop`/`*Mobile` — как в `Button`, `Input`.
- **Публичный API не расширяют «на будущее».** Команда добавляет props атомарно, по запросу: «чтобы зоопарк пропсов не увеличивать». Prop, который в этом PR ничем не используется, — finding.
- **`index.ts` не экспортирует лишнее:** тип или утилита, нужные только внутри пакета, наружу не отдаются (и помни про `shared/index.ts` — см. `references/public-api.md`).
- **Desktop-, mobile- и responsive-реализации одного компонента меняются согласованно.** Правка поведения только в одной из них — finding, если различие не объяснено платформой.
- **Не дублировать то, что уже есть в `@alfalab/core-components-shared`, `@alfalab/core-components-mq`, `@alfalab/hooks` и утилитах пакета.** Прежде чем принять новый хелпер или хук, поищи готовый: `isClient` и `getDataTestId` (`shared`), `useMatchMedia` и `useIsDesktop` (`mq`), `useLayoutEffect_SAFE_FOR_SSR` и `useFocus` (`@alfalab/hooks`) и другие.
- **Чинить надо в том пакете, где причина.** Типовой отказ в ревью: правка в `universal-modal`, когда причина в `base-modal`; фикс в компоненте, когда его место в общей утилите. Заплатка в вышестоящем пакете вместо исправления причины — finding.

## Мелкие упрощения

Лишние проверки, переменные и обёртки: `Boolean(x)` внутри условия, тернарник вместо `a || b`, промежуточная переменная на одно использование. Мейнтейнеры пишут такое постоянно, но это всегда P3: одно замечание на PR, не по одному на каждое место.

## CSS и токены

- **Захардкоженные цвета, отступы, радиусы — вместо них токены:** `--gap-*` (`packages/vars/src/gaps.css`), `--color-*`, `--border-radius-*` (`packages/vars/src/border-radius.css`). Нужного токена нет — это повод его завести, а не написать `10px`.
- **Прежде чем заводить свою переменную, проверь готовые наборы** в `packages/vars/src/` — в том числе `safe-area.css` (`--sat`, `--sab` и другие поверх `env(safe-area-inset-*)`) и миксины в `mixins.css`. Частый вопрос ревьюера — «для чего переменные заведены?»: переменная ради одного значения не нужна.
- **Объявления переменных — в `:root`.**
- **Нейминг переменных:** порядок «префикс + компонент + свойство», модификатор — в конце (`...-inverted`).
- **Правила внутри медиазапроса не выносят наружу.** Правка «для PWA» (`@media (display-mode: standalone)`) или для конкретного брейкпоинта, перенесённая за пределы своего медиазапроса, меняет поведение для всех остальных случаев.
- **Логика на строке `var(--foo)` в JS** ломается у потребителей, собирающих библиотеку без CSS-переменных, — см. `references/platform-and-performance.md`.

## Severity

| Ситуация | Severity |
|---|---|
| Нарушение соглашения из этого файла в новом или изменённом коде | **P2** |
| Новый публичный prop, который в PR ничем не используется | **P2** |
| Заплатка в вышестоящем пакете вместо исправления в пакете-причине | **P2** |
| Поведение изменено только в одной из desktop/mobile-реализаций без объяснения | **P2** |
| Новый хелпер или хук дублирует готовый из `shared`, `mq` или `@alfalab/hooks` | **P2** |
| Захардкоженное значение там, где есть готовый токен | **P2** |
| Лишние проверки, обёртки, промежуточные переменные | **P3**, одно замечание на PR |
| То же самое в коде, который PR не трогает | не finding |
