# Code Review: feat/DS-9709 — AccountSelect

## Summary

PR добавляет новый пакет `@alfalab/core-components-account-select` — составной компонент выбора счёта/карты с поддержкой добавления новой карты (многошаговый ввод номера, срока действия и CVC). Изменения качественные: валидация и форматирование покрыты unit-тестами, реализованы mobile/desktop варианты, есть changeset с `major`-бампом и фразой про новый компонент.

- 1 P2
- 2 P3

Общий вердикт: **обратить внимание** на P1 (доступность ввода карты для скринридеров) перед мержем; остальное — некритично.

## Findings

### P1 — Ввод данных карты полностью скрыт от скринридеров (`aria-hidden='true'` на контейнере полей)

`packages/account-select/src/components/multi-step-card-input/index.tsx:206`

**Проблема:** весь контейнер карточного ввода обёрнут в `<div className={styles.multistepCardInputWrapper} aria-hidden='true' ...>` (index.tsx:206). Внутри находятся три `<input>` — номер карты, срок действия, CVC — то есть **все поля основного сценария компонента** (добавление новой карты).

**Почему это проблема:** `aria-hidden='true'` исключает элемент и всех его потомков из accessibility-дерева. Скринридер (VoiceOver, NVDA, JAWS) не увидит ни одного поля ввода номера карты, срока действия и CVC — ни их `name`/подписи, ни возможность ввода. Атрибуты `placeholder`, `pattern`, `inputMode`, `aria-*` на самих инпутах в этом случае бесполезны, так как AT до них не доходит. По чек-листу скила это недоступность основного сценария компонента, а не edge case.

**Влияние:** пользователь скринридера не может добавить новую карту — ключевой функционал компонента оказывается полностью недоступен. При этом вся вложенная разметка (в т.ч. атрибуты доступности) создаётся в расчёте на AT, что указывает на непреднамеренность.

**Рекомендация:** убрать `aria-hidden='true'` и вместо этого:
- связать поля с доступными именами (собственный `<label>` или `aria-label` на каждом инпуте — `placeholder` ненадёжен для скринридеров и исчезает после ввода);
- если поле временно скрыто по шагам (номер → срок → CVC), скрывать его так, чтобы оно оставалось доступным для фокуса/чтения на своём шаге (например, управлять `tabIndex` и `hidden` уже есть — убедиться, что оно не `aria-hidden`);
- при завершении ввода / появлении ошибки — использовать live-регион (`role='status'`/`aria-live='polite'`, скрытый через `visually-hidden`, а не `display:none`), как в `pass-code`.

### P2 — Prop `client` у responsive-компонента не подключён к `useIsDesktop`

`packages/account-select/src/Component.responsive.tsx:8`

**Проблема:**

```tsx
const isDesktop = useIsDesktop(breakpoint);

if (isDesktop || client === 'desktop') { ... }
```

**Почему это проблема:** по публичному контракту (`types.ts`) `client?: 'desktop' | 'mobile'` документирован как «Версия, которая будет использоваться при серверном рендеринге». Но `client` не передаётся в `useIsDesktop` вторым аргументом (defaultValue), как это делает эталонный паттерн `Button`:

```tsx
// packages/button/src/Component.responsive.tsx
const defaultMatchMediaValue = client === undefined ? undefined : client === 'desktop';
const isDesktop = useIsDesktop(breakpoint, defaultMatchMediaValue);
```

`useIsDesktop` без defaultValue опирается на дефолт `useCoreConfig` → первый (в т.ч. серверный) рендер детерминируется не фактом `client`, а дефолтной конфигурацией. `client === 'mobile'` вообще не форсирует mobile-ветку (условие `isDesktop || client === 'desktop'` при `client === 'mobile'` и `isDesktop === true` вернёт desktop).

**Влияние:** на серверном рендере и первом клиентском рендере выбор десктопной/мобильной версии происходит не по переданному `client`, что грозит hydration mismatch и противоречит заявленному контракту пропа. Потребитель, заранее знающий контекст (например, через User-Agent на сервере) и передавший `client='mobile'`, не получит ожидаемой мобильной версии в первом рендере, если `matchMedia`/дефолт отдаёт desktop.

**Рекомендация:** подключить `client` как второй аргумент `useIsDesktop` по образцу `Button`:

```tsx
const defaultMatchMediaValue = client === undefined ? undefined : client === 'desktop';
const isDesktop = useIsDesktop(breakpoint, defaultMatchMediaValue);
```

### P3 — Сторисы импортируют компоненты относительным путём вместо собранного пакета

`packages/account-select/src/docs/Component.stories.tsx:5`

**Проблема:** для стóрис используются относительные импорты `from '../desktop'`, `from '../mobile'`, `from '../shared'` вместо `@alfalab/core-components-account-select/...`.

**Почему это проблема:** по конвенции проекта Storybook на gh-pages собирается из rollup-сборки пакета, а не из исходников; относительный импорт — исключение только для `<ArgsTable of={ComponentName}>`. (В `development.mdx` относительный импорт для `ArgsTabs components={{...}}` — легитимное исключение.)

**Влияние:** рассинхронизация между тем, что увидят в демке и что реально публикуется; потенциальные расхождения демки с итоговой сборкой пакета.

**Рекомендация:** импортировать из `@alfalab/core-components-account-select/desktop`, `/mobile`, `/shared`.

### P3 — CVC скрывается только через `-webkit-text-security` (не работает в Firefox, значение открыто в DOM)

`packages/account-select/src/components/multi-step-card-input/index.module.css:69` (и `index.tsx`, где CVC-инпут имеет `type='text'`)

**Проблема:** маскирование введённого CVC реализовано только CSS-свойством `-webkit-text-security: disc` (+ `text-security-disc`, поддерживается только в WebKit/Blink).

**Почему это проблема:** в Firefox (входит в поддерживаемые браузеры проекта) `-webkit-text-security` не применяется, и только что введённый CVC отображается открытым текстом. Помимо визуального, сам `<input type='text'>` хранит CVC открытым значением в DOM.

**Влияние:** на части аудитории CVC виден на экране при вводе — чувствительные данные карты. Ниже по приоритету, чем interactions/a11y, но затрагивает безопасность восприятия.

**Рекомендация:** для поля CVC использовать `type='password'` (с переключением по месту ввода) либо нативный `-webkit-text-security`-аналог с фолбэком; как минимум — задокументировать ограничение для Firefox.

## Positive observations

- Новый пакет оформлен по спецправилу: `major`-changeset с фразой про новый компонент и версия `0.0.0` в `package.json`.
- Хорошее покрытие unit-тестами валидации (`validate`, `parse-date`, `formaters`) и сложного поведения ввода (валидация «pristine» полей, сброс данных карты при смене выбранной опции, backspace перед слэшем в сроке действия, идентичность контракта `onInput`/`onSubmit`).

- CSS-правила (импорт `@import vars`, отсутствие класса `default`) соблюдены.
- Сторонние зависимости декларированы в `package.json` пакета и корне.
